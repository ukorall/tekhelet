# content/

תיקיית תוכן שמנוהלת בנפרד מהקוד של האפליקציה (`app/src/main/`), כדי שאפשר יהיה
להוסיף תמונות וטקסטים בלי לגעת ב-JSON או בקוד בכלל. בזמן ה-build (ראו
`syncContentImages` ו-`syncContentTexts` ב-`app/build.gradle.kts`) הקבצים כאן
מועתקים אוטומטית לתוך `app/src/main/assets/`, ומשם האפליקציה קוראת אותם. אין
צורך להריץ שום דבר ידנית - מספיק להוסיף קובץ כאן ולבנות (`./gradlew
assembleDebug`, או פשוט לדחוף ל-git ולתת ל-CI לבנות).

## images/ - תמונות של שיטות קשירה

מבנה: `content/images/<method-id>/<כל שם קובץ>.jpg` (גם `.png`/`.webp` עובדים).
ה-`method-id` הוא בדיוק ה-`id` שמופיע ב-`app/src/main/assets/methods.json`
(למשל `rambam`, `raavad`, `chinuch`, `gra`, `chassidic-arizal`, `aruch-mix`,
`rav-nagen`). בתוך כל תיקיית שיטה אפשר לשים כמה תמונות שרוצים, בכל שם קובץ -
האפליקציה מוצאת אותן אוטומטית לפי שם התיקייה (`AssetImages.kt`), אין צורך
לרשום את שמות הקבצים באף מקום.

אם לשיטה מסוימת עדיין אין תמונה, האפליקציה מציגה placeholder כללי (איור
מופשט של פתיל) במקומה - אין צורך "למלא" תיקיות ריקות.

תיקיות השיטות הקיימות כבר מוכנות כאן (ריקות) - פשוט לגרור תמונה פנימה.

## texts.txt - טקסטים חופשיים

קובץ טקסט יחיד. כל בלוק מתחיל בשורת כותרת `### <method-id>.<field>`, והטקסט
שאחריה (עד הכותרת הבאה או סוף הקובץ) הוא הערך. שדות נתמכים כרגע: `shortSummary`,
`fullDescription`, `editorialNote` - בדיוק השדות המקבילים ב-`methods.json`.
בלוק כזה **דורס** את הערך המקביל מ-`methods.json` עבור אותה שיטה; שיטה בלי
בלוק כאן ממשיכה להשתמש בטקסט שכבר יש לה ב-JSON. אפשר להוסיף בלוקים בהדרגה -
אין צורך לכסות הכל בבת אחת.

דוגמה:

```
### raavad.editorialNote
לפי הניתוח בשיחות המקור: "הפשרה הכי טובה בין הפסוקים לגמרא..." וכו'.
אפשר לכתוב כאן כמה שורות שרוצים, עד לכותרת ה-### הבאה.

### chinuch.fullDescription
טקסט מלא חדש לשיטת החינוך...
```

בשלב הזה (v0.1) הקובץ ריק מבלוקים פעילים - כל התוכן עדיין ב-`methods.json`
ישירות. אפשר להתחיל להעביר טקסטים לכאן בכל שלב.
